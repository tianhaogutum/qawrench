# qawrench a11y

`qawrench a11y` (formerly `a11y-baseline-bridge`) is an offline CLI/library that
catches a new accessibility finding even when another finding disappears and the
total stays the same. It reads saved axe or Pa11y CI JSON, compares occurrence
identities as a multiset, and writes a complete delta plus optional SARIF 2.1.0.

## Install

Requires Python 3.11 or newer. No runtime dependencies, Node.js, browser, network
access or scanner installation are needed to run it.

```sh
pipx install qawrench          # or: pip install qawrench
qawrench a11y --version        # prints the bare qawrench version, e.g. 0.1.0

# Or run without installing:
uvx qawrench a11y --help
```

`python -m qawrench a11y` is equivalent to `qawrench a11y`.

## Working examples

All supplied reports are **synthetic offline fixtures**; see [examples](../examples/a11y/README.md).
No URLs below are fetched.

```sh
qawrench a11y baseline \
  --format axe --url https://fixture.test \
  examples/a11y/axe-before.json --out /tmp/a11y-baseline.json

qawrench a11y diff \
  --format axe --url https://fixture.test \
  --baseline /tmp/a11y-baseline.json examples/a11y/axe-after.json \
  --out /tmp/a11y-delta.json --sarif /tmp/a11y.sarif
```

The second command succeeds in report-only mode and prints these counts:

```json
{"baseline":1,"current":1,"fixed":1,"new":1,"unchanged":0}
```

`#old-logo` is fixed, but `#new-promo` is new. The delta includes complete `new`
and `fixed` findings, and paired `baseline`/`current` findings for every unchanged
occurrence. Original reports are retained under `sources`, including extra native
fields. Snapshots retain their original report under `source.report`, with both
normalized findings and native rule/node or issue data. Pass and inapplicable
results are retained there but do not become violation findings.

To fail CI on new serious/critical findings, add `--fail-on serious` to `diff`.
It writes the reports and exits **1** for this fixture despite equal totals.
Severity choices are `minor`, `moderate`, `serious`, `critical`; `none` (default)
only reports. **Exit 0** means processing succeeded and the configured gate passed;
**exit 2** means invalid/unsupported/incomplete input, incomparable reports,
argument errors or an I/O failure. These codes do not indicate certification.

Pa11y CI uses the **combined results object**, not a bare issue list or standalone
Pa11y page result. Its report has no version metadata; attest the input version:

```sh
qawrench a11y baseline \
  --format pa11y-ci --input-version 4.0.0 \
  examples/a11y/pa11y.json --out /tmp/a11y-pa11y-baseline.json

qawrench a11y diff \
  --format pa11y-ci --input-version 4.0.0 \
  --baseline /tmp/a11y-pa11y-baseline.json examples/a11y/pa11y.json \
  --out /tmp/a11y-pa11y-delta.json --sarif /tmp/a11y-pa11y.sarif --fail-on minor
```

This produces two unchanged findings and exits 0. To validate and summarize without
writing anything, append `--dry-run` to either command. Paths must still be valid;
it never executes scripts or fetches URLs. Output directories must already exist.
Inputs/baselines cannot be overwritten by outputs. Each artifact is written by
atomic replacement, but the JSON/SARIF pair is **not a cross-file transaction**;
an I/O failure on the second file can leave the first written.

Ordinary `diff --sarif` locations encode URI-invalid characters independently of
native identity. For example, retained `properties.pageUrl`
`https://fixture.test/購物?b=2&a=%2f&say="yes"#區` has artifact URI
`https://fixture.test/%E8%B3%BC%E7%89%A9?b=2&a=%2f&say=%22yes%22#%E5%8D%80`.
UTF-8/quotes and brackets outside the authority are escaped; only the first `#`
is a fragment delimiter. IPv6 authorities, reserved delimiters, query order and
existing percent escapes (including case) remain intact. Literal and already-encoded
native pages remain distinct identities even when their artifact URIs coincide.
This changes no native URL normalization, message, rule/help metadata, finding,
`baselineState`, fingerprint, duplicate ordinal, severity, gate or review audit.
The constrained diff schema treats `pageUrl` as native HTTP(S) identity text and
checks artifact locations as URIs; the bridge still performs native validation.

## Reviewed exceptions

`diff --exceptions /path/to/reviewed-exceptions.json` applies explicit, temporary
reviews to the new-only severity gate. A review file is separate from the native
report and baseline. Its exact format is:

```json
{
  "schemaVersion": 1,
  "kind": "a11y-reviewed-exceptions",
  "identityPolicy": "engine-page-rule-full-target/sha256-v1",
  "exceptions": [
    {
      "engine": "axe",
      "page": "https://fixture.test/",
      "rule": "image-alt",
      "target": ["#new-promo"],
      "owner": "fixture-team",
      "reason": "Synthetic review pending replacement of this one asset",
      "expires": "2026-12-01",
      "maxOccurrences": 1
    }
  ]
}
```

All fields are required; unknown fields, duplicate normalized identities,
blank owners/reasons, invalid dates and nonpositive/noninteger budgets fail with
exit **2**, before either report is written. An empty `exceptions` array is valid.
The engine, normalized page, native rule and full native target use the same
identity policy as baselines below. Fields match literally, without globbing or
cross-runner aliases; Pa11y targets are strings (including `""`), axe targets retain
frame/shadow arrays. The file must be maintained through your own review process;
owner/reason text does not authenticate approval.

`expires` is a strict `YYYY-MM-DD` date. A review expires at **00:00 UTC on that
date**, using the execution clock, never the scan timestamp. For deterministic
library replay, `compare(..., exceptions=document, evaluation_date=date(2026, 11, 11))`
accepts a `datetime.date`; the CLI always uses the current UTC date.

`maxOccurrences` bounds the **total current occurrences** of that identity.
Unchanged occurrences consume the allowance first; only the remaining allowance
can except new occurrences. A review for one existing occurrence cannot hide an
additional duplicate. Pairing and allowance assignment follow the deterministic
metadata ordering described below. The review does not bind diagnostic metadata
or severity; those remain excluded from identity. Review the count and exact
target carefully and use a short expiry.

No finding is removed or relabeled: `new`, `fixed`, `unchanged` and their counts
remain complete. Excepted new findings carry `reviewedException` with the full
review and fingerprint. `gate.newAtOrAboveThreshold` stays the raw count;
`exceptedNewAtOrAboveThreshold` and `unexceptedNewAtOrAboveThreshold` explain the
gate decision. Only the latter can cause exit **1**. With `--fail-on none`, all
threshold counters stay zero while the review audit still runs.

JSON `exceptions` and SARIF run `properties.exceptions` retain **every** review,
its fingerprint, evaluation date, status, current/unchanged/excepted-new counts,
and owner/reason/expiry. An entry is `expired` when its date has arrived,
`unmatched` when unexpired but absent from the current findings, and `active`
otherwise. Expired takes precedence when both apply; `currentOccurrences: 0`
still shows the absence. Expired/unmatched entries waive nothing. They remain
visible even in report-only mode, but do not independently fail the new-only gate.
SARIF keeps all results and places the applicable review in each excepted new
result's `properties.reviewedException`; it does not emit SARIF suppressions.
CLI summaries (including `--dry-run`) show review-status and excepted-new counts.

Using the baseline from the first working example:

```sh
qawrench a11y diff \
  --format axe --url https://fixture.test \
  --baseline /tmp/a11y-baseline.json examples/a11y/axe-after.json \
  --exceptions examples/a11y/reviewed-exceptions.json --fail-on serious \
  --out /tmp/a11y-reviewed-delta.json --sarif /tmp/a11y-reviewed.sarif
```

On **2026-11-11**, this synthetic example exits **0** with raw `new=1`, `fixed=1`
and review counts `active=1`, `expired=1`, `unmatched=1`, `exceptedNew=1`.
Without the file it exits **1**. At/after **2026-12-01** the promotional review is
expired and this same command exits **1**, with all findings and reviews written.
A different target or an additional same-target occurrence is not covered by its
one-occurrence allowance. Exception files receive the same overwrite protection
as native inputs and baselines, including hardlinks.

### Draft a review from a delta

`draft-exception` copies an exact current identity into a **new review file**
that `diff --exceptions` can read. By default it contains one entry; optional
`--existing-reviews PATH` preserves a maintained file's entries and adds one.
Select the full lowercase SHA256
`fingerprint` from a `new` finding or an `unchanged[].current` finding in the saved
delta. Supply the owner, reason and expiry explicitly:

```sh
# Using /tmp/a11y-delta.json from the first working example:
FINGERPRINT=$(python3 -c 'import json; print(json.load(open("/tmp/a11y-delta.json"))["new"][0]["fingerprint"])')
qawrench a11y draft-exception /tmp/a11y-delta.json \
  --fingerprint "$FINGERPRINT" --owner fixture-team \
  --reason 'Synthetic review pending replacement of this one asset' \
  --expires 2026-12-01 --out /tmp/a11y-draft-review.json
```

This exits **0**, writes the review format above with `target: ["#new-promo"]`
and `maxOccurrences: 1`, and prints `dryRun`, the selected `fingerprint` and
`maxOccurrences`. The complete native target is preserved, including axe frame
and shadow arrays or Pa11y's empty page-level selector. The budget counts **all
current occurrences of that exact identity**, new plus unchanged, rather than
just the new count. Fixed occurrences are excluded. An unchanged-only identity
is selectable; a fixed-only identity is not.

The command requires a schema-1 `a11y-delta` produced by `diff`, with complete
retained sources. It recomputes the delta from those sources and checks its
findings, fingerprints, counts, gate and review audit for consistency. A previously
reviewed delta is replayed at its recorded evaluation date. This does not
authenticate the saved reports. Migration diagnostics, native reports, baselines,
inconsistent deltas, unknown or partial fingerprints, and invalid/blank review
fields return **2** without creating output. Expiry follows the review schema:
an already expired date is valid but will waive nothing when applied.

`--out` must be a **new file in an existing directory**; existing files, hardlinks
and symlinks are refused. The completed draft is published atomically without
replacing an existing destination. `--dry-run` performs the same validation and
prints the summary without writing. Review the draft through your own approval
process, then pass it to `diff --exceptions`.
Drafting alone changes no gate or baseline and does not authenticate approval.

To add the selected identity to an existing review document, using the same delta
and fingerprint above:

```sh
qawrench a11y draft-exception /tmp/a11y-delta.json \
  --fingerprint "$FINGERPRINT" --owner fixture-team \
  --reason 'Synthetic review pending replacement of this one asset' \
  --expires 2026-12-01 --existing-reviews examples/a11y/reviews-to-extend.json \
  --out /tmp/a11y-extended-reviews.json

qawrench a11y diff \
  --format axe --url https://fixture.test --baseline /tmp/a11y-baseline.json \
  examples/a11y/axe-after.json --fail-on serious \
  --exceptions /tmp/a11y-extended-reviews.json --out /tmp/a11y-reviewed-delta.json
```

The draft exits **0** and reports `existingEntries: 2`, `addedEntries: 1`,
`totalEntries: 3` alongside the selected fingerprint and `maxOccurrences: 1`.
The two synthetic existing reviews (one expired, one unmatched) keep every field
value and budget. Applying the result exits **0** before the new review's
2026-12-01 expiry, retains raw counts (`new: 1`, `fixed: 1`) and audits all three
reviews. After expiry the serious gate exits **1** as expected.

Existing files must use the strict reviewed-exceptions schema above. Every
existing entry is deep-copied without changing its values, including URL spelling,
owner/reason whitespace, expiry and occurrence budget; expired and unmatched
entries are retained. The combined entries are sorted by canonical JSON (sorted
object keys, compact separators), so input entry order does not affect output.
JSON whitespace/key layout is reformatted. URL normalization is used for identity
validation, including duplicate detection, without rewriting existing entries.

An identity already present in the existing document is rejected, even if expired
or its budget is smaller than the current count. This command never renews,
replaces, expands or prunes an existing review. Duplicate normalized identities
within the existing file, malformed/extra fields, JSON `null`, duplicate JSON
keys and unreadable paths also return **2** without writing, including in dry-run.
An empty `exceptions: []` is valid. Both input files remain untouched; use a new
output path, review it, then deliberately adopt it as your maintained file.

## Rule-version migration diagnostics

Use `migration` to review saved scans when upgrading rules, including axe-core
**4.10.3 → 4.11.0**, or a Pa11y runner/custom rule set within Pa11y CI **4.0.0**.
It requires an explicit map; it never guesses aliases from similar messages.

```sh
qawrench a11y baseline \
  --format axe --url https://fixture.test examples/a11y/migration-before.json \
  --out /tmp/a11y-migration-baseline.json

qawrench a11y migration \
  --format axe --url https://fixture.test \
  --baseline /tmp/a11y-migration-baseline.json examples/a11y/migration-after.json \
  --rule-map examples/a11y/rule-migration.json --out /tmp/a11y-migration.json
```

These **synthetic custom-rule** fixtures produce exit **0** and counts:

```json
{"added":1,"baseline":2,"current":2,"removed":1,"renamed":1,"unchanged":0}
```

`legacy-name` → `replacement-name` on `#shared` is paired under `renamed`;
`#removed` stays `removed`, and `#added` stays `added`. The names in this example
are not real upstream aliases. The complete map format is:

```json
{
  "schemaVersion": 1,
  "kind": "a11y-rule-migration",
  "baseline": {
    "format": "axe",
    "inputVersion": "4.10.3",
    "ruleSet": "fixture-rules-v1"
  },
  "current": {
    "format": "axe",
    "inputVersion": "4.11.0",
    "ruleSet": "fixture-rules-v2"
  },
  "renames": [
    {
      "engine": "axe",
      "from": "legacy-name",
      "to": "replacement-name",
      "reason": "Synthetic custom-rule rename, not an upstream alias"
    }
  ]
}
```

Every field is required; extra fields fail. `baseline`/`current` format and input
version must match the validated snapshots. `ruleSet` is a nonblank caller label,
retained for audit, not automatic discovery or verification of runner versions.
For Pa11y, use `format: "pa11y-ci"`, `inputVersion: "4.0.0"` on both sides and
engine `pa11y-ci/htmlcs` or `pa11y-ci/axe` in each rename. Pa11y's combined export
has no runner-version metadata: retain that provenance yourself in the labels.
A map must come from your own rule-change review; `reason` is retained verbatim.

Exact identities pair first as `unchanged`; declared renames then pair only in
the **same namespace, normalized page and full native target**, counting duplicates
individually. Original rule IDs, fingerprints, native findings and both sources
stay intact. Each rename is audited with `matchedOccurrences` and `matched` or
`unmatched` status, including unused entries. With `renames: []`, all differing
rule IDs remain added/removed. Multiple mappings are allowed, but reused endpoints,
chains, merges and splits are rejected as ambiguous. A source ID still violating
in the current report, or a destination ID already violating in the baseline,
also makes the declared rename ambiguous and fails conservatively.

`removed` means a target violation is absent from the current report; it does
**not** prove remediation or rule retirement. A changed detector, scope not exported
by the scanner, or real page edits can also explain absence. `added` means an
unpaired current occurrence; a new rule can explain it without a page regression.
The report describes observed occurrences after applying caller-declared aliases.
Without catalog inputs, it does not inventory the scanners' rule catalogs.

Both inputs receive the usual native failure/completeness and snapshot consistency
checks. Page coverage and axe `toolOptions` must still match exactly. Unknown
versions, bad/ambiguous maps, incomplete or failed scans return **2** before writing
output; a failed scan never becomes an empty current report. Map files get the
same input/hardlink overwrite protection. `--dry-run` validates and prints counts
without writing. Exit **0** means diagnostics succeeded, including when findings
were added; this command has no severity gate, exceptions or baseline rewrite.
Ordinary `diff` still requires identical input versions and retains its existing
severity policy. A migration map never transfers reviewed exceptions to a new ID.

Library entry points are `diagnose_migration(baseline, current, map_document)` and
`validate_migration(map_document)`; invalid inputs raise `BridgeError`.

### Migration notes for CI review

Add `--output-format sarif` to write **SARIF 2.1.0 observation notes** to `--out`.
`--format axe|pa11y-ci` still selects the native input dialect. The default
`--output-format json` preserves the existing diagnostic JSON and summary; neither
output mode changes the exit policy. To retain both artifacts, run migration once
per output format with different output paths.

After the synthetic baseline command above, this installed console-script example
writes a CI review artifact without running a scanner or uploading anything:

```sh
qawrench a11y migration \
  --format axe --url https://fixture.test \
  --baseline /tmp/a11y-migration-baseline.json examples/a11y/migration-after.json \
  --rule-map examples/a11y/rule-migration.json \
  --output-format sarif --out /tmp/a11y-migration.sarif
```

This produces three `level: "note"` results, one each for the existing `added`,
`removed` and `renamed` observations, under diagnostic rule IDs
`a11y-migration/added`, `a11y-migration/removed` and `a11y-migration/renamed`.
Unchanged occurrences remain in run counts and do not produce migration notes.
Every note warns: **Disappearances do not establish fixes or target retesting.**
Aliases are caller-declared; coverage counts are shared report observations,
not occurrence-specific execution or remediation evidence.

The human-readable message identifies the literal native `engine`, `rule`, full
`target` and `page`: `Current identity: engine="axe", rule="replacement-name",
target=["#added"], page="https://fixture.test/".` Removed notes label the baseline
identity; renamed notes show both baseline and current identities. Each page is
copied from that side's retained native finding, without re-normalizing or taking
it from catalogs, aliases or a fallback URL. Copied messages distinguish identical
selectors on distinct pages. Compact JSON quoting preserves nested arrays,
selector order/whitespace, Unicode, quotes, query ordering, percent-escape case,
fragments and Pa11y's empty `target=""`. Repeated pairs repeat their native page.
No target is shortened or translated into a source location.

Renamed notes also label `Caller-declared rename rationale: "...".` using only
the explicit audit record matching the native engine, baseline rule and current
rule. Removed notes with an existing `mappedRuleCoverage.reason` separately label
`Caller-declared mapped-rule rationale: "...".` using that annotation alone.
The reason is JSON-quoted with literal Unicode; leading/trailing spaces, quotes,
backslashes and escaped newlines/tabs are retained. Repeated pairs repeat the
same rationale. A missing applicable record/reason adds no clause: no audit-only
rationale is backfilled onto removed leftovers without mapped coverage, and
added/unrelated notes do not acquire reasons from unmatched aliases. These are
caller declarations, not evidence of equivalence, execution or retesting.

When existing coverage annotations are present, the message also labels
**Baseline original-ID**, **Current original-ID** and **Current explicitly mapped**
observations separately. Page observations name the literal rule, existing status
and outcome groups; target observations name the rule/full target, existing
status and separate shared `violations`/`passes` native-node counts. For example:
`Current explicitly mapped target observation: rule="replacement-name",
target=["#removed"], status=no-observed-target-outcome, observed nodes:
violations=0, passes=0.` Unavailable annotations are omitted. Renamed notes do not
acquire coverage from the run catalog; added notes do not follow aliases backward.
These messages summarize the existing evidence without establishing regressions,
fixes, equivalent targets or occurrence-specific retesting.

Added/removed result `properties` copy the complete finding, including literal
`engine`, `rule`, `page`, `target`, `fingerprint`, native metadata and any separate
`ruleCoverage`, `ruleTargetCoverage`, `mappedRuleCoverage`,
`mappedTargetCoverage`, `baselineRuleCoverage` and `baselineRuleTargetCoverage`
fields. Renamed properties retain the complete `baseline` and `current` findings
separately. `observation` and a duplicate `occurrence`
ordinal describe the note. No selectors are flattened, trimmed or translated.
Run properties preserve sources, pages, counts, map audit, identity policy and
optional `ruleCatalogs`; missing catalogs never become fabricated coverage.

`partialFingerprints` retain native identity hashes separately as
`a11yMigrationBaselineIdentity/v1` and/or `a11yMigrationCurrentIdentity/v1`.
`a11yMigrationObservation/v1` is SHA256 of the bridge's canonical JSON array
`[observation, baselineFingerprintOrNull, currentFingerprintOrNull]`. Duplicates
share these fingerprints and receive separate ordinals. Rule descriptors and
results are sorted deterministically; identical inputs produce identical output
bytes. Native report/catalog ordering stays intact in provenance.

Locations contain only a URI representation of the retained observed page URL,
with no invented file or source line. In migration `artifactLocation.uri`, UTF-8
percent encoding escapes Unicode, quotes and other characters outside URI syntax.
For example, native `https://fixture.test/購物?b=2&a=%2f&say="購物"#區` becomes
`https://fixture.test/%E8%B3%BC%E7%89%A9?b=2&a=%2f&say=%22%E8%B3%BC%E7%89%A9%22#%E5%8D%80`.
Existing valid percent escapes (including case), query order, reserved delimiters,
IPv6 authority brackets and already-valid ASCII URIs stay intact. Brackets outside
the authority and extra `#` characters within a fragment are escaped. This does
not normalize native page identities or infer URL equivalence: messages, native
finding properties and run provenance retain the original values. Ordinary `diff`
SARIF locations retain their existing behavior.

Migration notes contain no `baselineState`, `fixes` or `suppressions` and
never transfer reviewed exceptions. The same completeness, paired-catalog,
alias/provenance and overwrite checks run before output; invalid inputs exit **2**
without creating or replacing the artifact, and `--dry-run` writes nothing.
CI viewers may filter note-level results or require repository source locations;
this export does not guarantee that every viewer displays page-only diagnostics.

Library use: `migration_to_sarif(diagnose_migration(...))`. Like `to_sarif`, it
serializes bridge-produced output; it does not validate arbitrary edited diagnostic
documents. The separate offline structural contract is
`src/qawrench/a11y/schemas/migration-sarif-output.schema.json`. Ordinary `diff` SARIF and its
severity gate retain their existing semantics.
The 4.11.0 adapter accepts the full v1 result subset verified against the pinned
[axe 4.11.0 API](https://github.com/dequelabs/axe-core/blob/v4.11.0/doc/API.md) and
[types](https://github.com/dequelabs/axe-core/blob/v4.11.0/axe.d.ts).
No upstream scanner was executed.

### Optional exported rule catalogs (axe only)

For axe **4.10.3 / 4.11.0**, supply **both** `--baseline-catalog` and
`--current-catalog` to distinguish catalog absence from an occurrence disappearing
under a rule that is still available. Each input wraps the corresponding
unfiltered `axe.getRules()` array in this bridge-owned schema:

```json
{
  "schemaVersion": 1,
  "kind": "a11y-rule-catalog",
  "format": "axe",
  "inputVersion": "4.10.3",
  "ruleSet": "fixture-rules-v1",
  "export": {"api": "axe.getRules", "tags": null},
  "rules": [
    {
      "ruleId": "legacy-name",
      "description": "Synthetic description",
      "help": "Synthetic help",
      "helpUrl": "https://fixture.test/help",
      "tags": [],
      "actIds": []
    }
  ]
}
```

All envelope and rule fields shown are required except `actIds`. Unknown fields,
duplicate rule IDs, blank text, invalid HTTP(S) help URLs and non-string tag/ACT
entries fail. `tags`/`actIds` are arrays; empty arrays are valid. Empty catalogs
are valid only when consistent with reported outcomes and declared aliases.
`export.tags: null` attests that no tag filter was passed to `getRules()`; filtered
exports are rejected. The wrapper's version must match the validated scan, and
its `ruleSet` must match that side of the migration map. Capture the catalog
from the same configured engine as the scan, after custom-rule configuration;
include rules used in frames. Labels and export declarations are caller
attestations: consistency checks do **not** authenticate an export or establish
that a caller supplied every available rule. Absence means absent from the
supplied catalog, not proven upstream retirement.

Every rule ID reported in `violations`, `passes` or `inapplicable` must belong to
that side's catalog, even when it has no violation findings. Catalog mode validates
the result metadata, node arrays and native targets for these groups. Duplicate
IDs within a group fail; the same rule across different groups is valid.
Incomplete/failed scans still fail. Declared rename sources/destinations must
exist in their respective catalogs, even for unmatched aliases. Catalog rules
with no reported outcome are retained as coverage gaps; availability does not
establish that a rule was selected, enabled or run.

`ruleCatalogs.baseline` and `.current` retain the complete `catalog`, sorted
`reportedRules` entries (`rule`, `outcomes`) and `notReportedRules` IDs.
`ruleCatalogs.addedRules`/`removedRules` compare catalog IDs independently of
occurrence matching and declared aliases. Every unpaired `removed` finding gets
`ruleCoverage` with one of these statuses and its current `outcomes` array:

| Status | Evidence in supplied current inputs |
|---|---|
| `absent-from-current-catalog` | Original rule ID is absent from the catalog; outcomes are empty |
| `reported-in-current` | Rule ID has one or more outcome groups in the same page report |
| `not-reported-in-current` | Catalog contains the rule ID, but the report has no outcome for it |

Outcomes preserve `passes`, `violations` and `inapplicable` separately.
`inapplicable` means no matching content was found, not that targets passed.
A pass or violation on another node does not establish that the removed target
was tested or fixed. These annotations never change occurrence counts, rename
pairing or severity policy. With no catalogs, the existing output shape is retained.

Every catalog-mode removed occurrence also gets `ruleTargetCoverage`, without
requiring an alias. It retains the **original rule ID and full native target**,
counting all current native `violations` and `passes` nodes for that exact ID and
target. For example, two leftovers can each carry this observation:

```json
{
  "ruleTargetCoverage": {
    "rule": "legacy-name",
    "target": ["iframe#checkout", ["checkout-shell", "button.buy"]],
    "status": "observed-target-outcome",
    "observedNodes": {"violations": 1, "passes": 2}
  }
}
```

Both counts are always present. With no matching nodes, `status` is
`no-observed-target-outcome` and both counts are zero. This includes an original
ID absent from the current catalog, a cataloged ID with no outcome, inapplicable
results, and results only at other targets. `ruleCoverage` retains the separate
page/rule status that distinguishes these cases. Same-target results under another
rule ID never contribute, including a declared destination ID.

Every catalog-mode **added** occurrence gets two separate baseline observations,
using its literal current rule ID without following aliases backward:

| `baselineRuleCoverage.status` | Evidence in supplied baseline inputs |
|---|---|
| `absent-from-baseline-catalog` | Current rule ID is absent from the baseline catalog; outcomes are empty |
| `reported-in-baseline` | That literal ID has one or more baseline outcome groups |
| `not-reported-in-baseline` | Baseline catalog contains the ID, but the report has no outcome for it |

`baselineRuleCoverage.outcomes` lists the sorted baseline groups, preserving
`passes`, `violations` and `inapplicable` separately. `baselineRuleTargetCoverage`
counts baseline native violation/pass nodes at the exact full target. For example:

```json
{
  "baselineRuleCoverage": {
    "status": "reported-in-baseline",
    "outcomes": ["inapplicable", "passes", "violations"]
  },
  "baselineRuleTargetCoverage": {
    "rule": "same-rule",
    "target": ["iframe#checkout", ["checkout-shell", "button.buy"]],
    "status": "observed-target-outcome",
    "observedNodes": {"violations": 1, "passes": 2}
  }
}
```

Both target counts are always present. With no matching baseline nodes, status
is `no-observed-target-outcome` and both counts are zero, including catalog absence,
unreported/inapplicable rules and outcomes only at other targets. Other IDs,
flattened or reordered paths and changed selector text never contribute.

These baseline counts are shared observations too. If one baseline violation pairs
unchanged with one of three current occurrences at that target, both added
leftovers still report that one baseline violation. Baseline passes at the target
are counted independently, including duplicates. Never allocate baseline nodes to
leftovers or sum the annotations as distinct evidence. Added occurrences do not
establish regressions; a prior same-target pass does not establish occurrence-specific
execution or equivalent rule/DOM semantics. A declared destination ID absent from
the baseline catalog stays absent even when its source ID has baseline outcomes.
Renamed pairs receive no added-occurrence annotations. These fields require both
catalogs and are retained verbatim in added SARIF note properties, with no
`baselineState`, fixes or suppression semantics.

For a removed occurrence whose `(engine, rule)` is a declared rename source,
catalog mode also adds `mappedRuleCoverage`. Its `rule` is the literal destination
ID and `reason` is the declared rename reason, retained verbatim. `status` is
`reported-in-current` with the destination's sorted `outcomes`, or
`not-reported-in-current` with `outcomes: []`. The destination must belong to the
current catalog; an unknown endpoint still fails validation before writing.
For example, a leftover `legacy-name` occurrence can have both:

```json
{
  "ruleCoverage": {"status": "absent-from-current-catalog", "outcomes": []},
  "mappedRuleCoverage": {
    "rule": "replacement-name",
    "reason": "Synthetic custom-rule rename, not an upstream alias",
    "status": "reported-in-current",
    "outcomes": ["violations"]
  }
}
```

`ruleCoverage` always describes the original ID, even if that ID is still
cataloged or reported in a nonviolation group. `mappedRuleCoverage` describes the
destination rule in the current page report. It does not establish that the
removed target was tested or fixed: destination violations at another target,
passes, inapplicable results and no reported outcome all leave the occurrence
removed. Partial renames retain their paired occurrences and every duplicate or
nested leftover separately. No mapped field is added without both catalogs or
without an explicit source alias; no additional equivalence is inferred.

The same leftover also gets `mappedTargetCoverage`, which counts native current
nodes for the destination rule at its **exact full target**:

```json
{
  "mappedTargetCoverage": {
    "rule": "replacement-name",
    "target": ["#removed"],
    "status": "no-observed-target-outcome",
    "observedNodes": {"violations": 0, "passes": 0}
  }
}
```

`status` is `observed-target-outcome` when either count is positive; otherwise it
is `no-observed-target-outcome`. Both counts are always present. Target matching
preserves every selector, array order and frame/shadow nesting: a flattened path
or a selector with different whitespace does not match. Only destination-rule
`violations` and `passes` nodes contribute, each duplicate node separately.
`inapplicable` has no nodes and remains page/rule evidence in `mappedRuleCoverage`.
A destination violation elsewhere can therefore coexist with zero target counts.

These are **shared report observations**, not allocated matches for old occurrences.
For example, if three old occurrences at one nested target pair with one current
violation there, two leftovers remain. With two current pass nodes there as well,
each leftover reports `observedNodes: {"violations": 1, "passes": 2}`. The one
violation is already included in the renamed pair for `mappedTargetCoverage`, or
the unchanged pair for `ruleTargetCoverage` when the original ID still violates.
Both target fields use literal full targets, including nesting, selector order
and whitespace. Do not sum annotations across leftovers as distinct evidence,
subtract paired nodes, or use them as a remediation count. Same-target passes
do not prove occurrence-specific retesting, equivalent rule semantics or fixes.

The four current-report coverage fields on removed occurrences remain independent
of the two baseline fields on added occurrences. Original-ID fields require paired
catalogs; mapped fields additionally require an explicit source alias. Pairing,
counts, identities, native sources and audits are unchanged. No-catalog output is
unchanged. Malformed baseline or current pass nodes/targets, invalid catalog
provenance and unknown alias endpoints fail before creating or replacing output.

```sh
qawrench a11y baseline \
  --format axe --url https://fixture.test examples/a11y/catalog-migration-before.json \
  --out /tmp/a11y-catalog-baseline.json

qawrench a11y migration \
  --format axe --url https://fixture.test \
  --baseline /tmp/a11y-catalog-baseline.json examples/a11y/catalog-migration-after.json \
  --rule-map examples/a11y/rule-migration.json \
  --baseline-catalog examples/a11y/rule-catalog-before.json \
  --current-catalog examples/a11y/rule-catalog-after.json --out /tmp/a11y-catalog-migration.json
```

This **synthetic custom-rule** example exits **0** with `baseline=5`, `current=2`,
`renamed=1`, `added=1`, `removed=4`, `unchanged=0`. The remaining `legacy-name`
occurrence and `retired-rule` are absent from the supplied current catalog;
`still-rule` has an `inapplicable` result; `skipped-rule` is cataloged but has no
reported outcome. The `legacy-name` leftover also has `mappedRuleCoverage` for
`replacement-name` with status `reported-in-current` and outcomes `["violations"]`;
its `ruleCoverage` still reports the original ID's absence. Its
`mappedTargetCoverage` has target `["#removed"]`, status
`no-observed-target-outcome` and zero violations/passes: the destination's
violations are at other targets. `addedRules` is
`["replacement-name"]`, `removedRules` is
`["legacy-name", "retired-rule"]`. No disappearance is labeled a fix.

One-sided, malformed, filtered or inconsistent catalogs return **2** before
writing. Catalog files and hardlinks receive input overwrite protection;
`--dry-run` performs the same checks without writing. Pa11y catalogs are explicitly
unsupported: its combined export lacks per-rule nonviolation outcomes and runner
provenance. Use the existing occurrence-only migration mode for Pa11y.

Library calls accept `diagnose_migration(..., baseline_catalog=old_document,
current_catalog=new_document)`; `None` on both means omitted. `validate_catalog`
validates the envelope/metadata alone; migration additionally binds provenance
and checks coverage. CLI files containing JSON `null` are invalid catalogs.
The `getRules`/`RuleMetadata` shapes were checked against the pinned upstream sources;
no scanner was executed.

## Compatibility and identity policy

| Adapter | Tested input dialect | Namespace |
|---|---|---|
| `axe` | axe-core **4.10.3 / 4.11.0**, full `v1` `axe.run` JSON results | `axe` |
| `pa11y-ci` | Pa11y CI **4.0.0** combined JSON; Pa11y **9.0.0** issue shape | `pa11y-ci/htmlcs`, `pa11y-ci/axe` |

This is fixture-tested format compatibility, not a claim of running the upstream
scanners. Versions outside the table, unknown engines/runners, missing required
fields and malformed targets fail explicitly. axe's `testEngine` is verified; Pa11y CI does
not export CI/runner versions or configuration, so `--input-version` is a caller
attestation, not automatic version discovery. If a top-level version is supplied,
it must agree. `--url` supplies an axe URL only when absent; it is not an override.
Only absolute HTTP(S) page/help URLs are supported; file URLs are rejected.

The versioned fingerprint hashes canonical JSON of:

```text
[engine namespace, normalized page URL, native rule ID, full native target]
```

Normalization lowercases scheme/host, converts international hosts to IDNA,
canonicalizes IPv6, removes default ports and supplies `/` for an empty path.
It preserves path spelling, percent-escape spelling, query order/multiplicity and
fragments (including SPA routes). Empty query/fragment delimiters are dropped.
Credentials, whitespace, control characters and invalid percent escapes fail.
Selectors and rules are never trimmed, reordered, joined or translated.

axe targets retain the outer frame path and inner shadow selector arrays, e.g.
`["iframe#checkout", ["checkout-shell", "button.buy"]]`. Only the pinned dialect's
nonempty outer list of strings or shadow paths of at least two strings is accepted.
Pa11y selectors stay native strings, including `""` for page-level issues;
Pa11y's axe runner may already have flattened a target before exporting it.
This bridge cannot recover nesting absent from that input.

Matching excludes message/impact so a diagnostic edit does not change identity.
Duplicates share a fingerprint but are counted individually. Exact metadata
matches pair first; remaining duplicate pairs are matched canonically. Metadata
changes on existing identities remain unchanged and do not trigger the new-only
gate. axe native impacts map directly to gate levels; null/missing impact fails
any enabled gate conservatively. Pa11y native impact is preserved when supplied;
otherwise its `error`/`warning`/`notice` types map to serious/moderate/minor for the
gate, with absent native impact retained as null.

Baseline loading recomputes the snapshot from its native source and rejects
inconsistent stored findings/fingerprints. This checks consistency, not authenticity.
Comparison requires the same format/version and complete normalized page set,
and identical axe `toolOptions`. A removed page cannot appear as a clean fix.

## Completeness limits

- Nonempty axe `incomplete` is rejected, including legitimate manual review items.
  This conservative policy prevents aborted checks from passing as clean.
  Full result arrays and `toolOptions` are required. `selectors: false` and
  `resultTypes` excluding violations are rejected because target coverage can shrink.
- Pa11y page errors (including `{}` or message-only objects), missing/duplicate URL
  coverage, and inconsistent `total`/`passes`/`errors` counters are rejected.
  An empty run is not a clean report.
- **Pa11y CI can erase issues within per-page thresholds before exporting its
  combined report.** Produce inputs with per-page thresholds set to **0**, use
  identical runner/options/ignore settings, and include warnings/notices if wanted.
  These settings are not exported, so the bridge cannot detect prior suppression.
  Repeated scans of the same URL are unsupported because the URL map loses runs.
- axe custom rule/context configuration outside `toolOptions`, upstream filters,
  unscanned pages and upstream-truncated data cannot be reconstructed or detected
  reliably. Keep scan scope/configuration stable. Inputs are read fully in memory.

## SARIF and existing tools

For compatibility with existing SARIF consumers and baselines, `tool.driver.name`
remains `a11y-baseline-bridge`; `tool.driver.version` is the qawrench version.

SARIF 2.1.0 includes all new, unchanged and fixed occurrences (`baselineState`
`new`, `unchanged`, `absent`), namespaced native `ruleId`, rule indexes, stable
`partialFingerprints`, page artifact URLs and full selectors in result properties.
Duplicate occurrence ordinals supplement the shared identity fingerprint. It uses
supplied help links; when Pa11y supplies none it links to the runner project,
without inventing a rule-specific help URL. Emitted `rule.helpUri` escapes Unicode,
quotes, path/query brackets and extra `#` characters using URI-safe UTF-8 percent
encoding; retained finding `helpUrl` and native metadata stay literal. Existing
percent escapes, query ordering, reserved delimiters and IPv6 authorities are
preserved, with no URL equivalence inference. Rule selection/order and ASCII
fallback links stay unchanged. It invents no files or source line numbers.

[axe-sarif-converter](https://github.com/microsoft/axe-sarif-converter) already
converts axe results to SARIF. This tool's purpose is the multiset baseline and
new-identity gate across explicitly separate report namespaces.
[Pa11y CI](https://github.com/pa11y/pa11y-ci) remains the scanner/CI runner;
its thresholds are not replaced during scanning. HTML_CodeSniffer rule IDs and
axe IDs are never inferred equivalent, even when names or selectors look alike.
It supplies no accessibility certification, browser scanning or blanket suppression.
Synthetic tests do not prove any real-site improvement. Adoption, demand and
real-world performance gains remain unverified.

[axe target types](https://github.com/dequelabs/axe-core/blob/v4.10.3/axe.d.ts),
[Pa11y CI 4.0.0 API/reporters](https://github.com/pa11y/pa11y-ci/tree/4.0.0),

## Library and tests

```python
import json
from qawrench.a11y import make_baseline, compare, to_sarif

with open("examples/a11y/axe-before.json") as f:
    before = make_baseline(json.load(f), "axe", url="https://fixture.test")
with open("examples/a11y/axe-after.json") as f:
    after = make_baseline(json.load(f), "axe", url="https://fixture.test")
delta = compare(before, after, fail_on="serious")
assert delta["counts"]["new"] == delta["counts"]["fixed"] == 1
sarif = to_sarif(delta)
```

Malformed/unsupported library inputs raise `BridgeError` (a `ValueError`).
`validate_exceptions(document)` validates and normalizes a review file without
applying it. `compare(..., exceptions=document)` validates it again before use;
`exceptions=None` means no review file, preserving the previous output shape.
`to_sarif` accepts the delta produced by `compare`. For migration observation
notes, use `migration_to_sarif` as described above.
`draft_exception(delta, fingerprint, owner="team", reason="review context",
expires="2026-12-01", existing_reviews=review_document)` returns a validated union
with one new entry after validating the entire delta. Omit `existing_reviews`
for a one-entry document; explicit `None` is invalid. It does not mutate either
input or write files.

Tests run sequentially with offline fixtures and subprocess CLI E2E checks:
multiset counts, duplicate metadata pairing, nested target round trip,
URL policy, namespaced SARIF, severity gates, clean/failure paths, invalid JSON,
incomplete scans, coverage drift, input overwrite protection and dry-run behavior.
Review tests cover UTC-date expiry boundaries, stale entries, exact namespace and
nested-target matching, bounded duplicate allowances, invalid review files,
JSON/SARIF audit retention, dry-run summaries and exception-file overwrite protection.
Migration tests cover cross-version guards, explicit versus absent aliases, multiset
and nested-target pairing, Pa11y namespaces, complete-clean versus failed scans,
map validation/ambiguity, source consistency and CLI dry-run/path protection.
Catalog tests cover pinned metadata/provenance, all three disappearance states,
multiple outcome groups, coverage gaps, uncataloged outcomes and alias endpoints,
strict malformed/null inputs, Pa11y rejection and catalog hardlink protection.
Mapped coverage tests cover partial and unmatched renames, duplicate nested
leftovers, every destination outcome group and no outcome, independent original-ID
coverage, absent catalogs/aliases and invalid provenance/endpoints before writes.
Target observation tests cover shared duplicate-node counts, pass-only and mixed
outcomes, already-paired violations, exact nested versus flattened/reordered targets,
selector whitespace, other rules, no outcome, input immutability and malformed
pass targets rejected before creating or replacing output.
Original-ID target tests additionally cover alias-free same-rule passes, already
unchanged violations shared by duplicate leftovers, inapplicable-only and missing
outcomes, and original IDs absent from the current catalog.
Added-occurrence baseline tests cover all three page statuses, same-rule passes,
already-unchanged violations shared by duplicates, literal ID/target boundaries,
no reverse aliases, JSON/SARIF retention and baseline validation before either format writes.
Migration SARIF tests cover lossless original/mapped coverage, both rename identities,
stable fingerprints, deterministic duplicate ordering, note warnings, no-catalog and
empty-result output, Pa11y namespaces/empty selectors, dry-run and validation before writes.
Message tests additionally cover literal Unicode/escaped rule IDs, nested versus
flat/reordered targets, selector whitespace, both rename identities, separately
labeled baseline/current original/mapped page and target observations, missing
annotations, inapplicable/no-outcome gaps and duplicate shared counts.


The SARIF schema tests use the test-only `jsonschema` and `rfc3986-validator`
packages; `rfc3986-validator` registers `jsonschema`'s URI checker. Focused tests
explicitly require registration and reject literal Unicode/quotes, malformed percent
escapes, relative references and extra fragment delimiters; an unavailable checker
fails instead of skipping. The migration schema separately accepts retained native
HTTP(S) page identity text while enforcing URI format on artifact locations. This
constrained schema is not a replacement for the bridge's native URL validation.
Native URL acceptance is otherwise strict, but escaped unpaired surrogates in URL
paths can still pass adapters and then fail UTF-8 SARIF encoding; that is a known
boundary.

Draft tests cover full native targets, total current budgets across new/unchanged
duplicates, fixed-only/unknown identities, historical review replay, inconsistent
deltas, explicit review metadata, preservation of existing entries, deterministic
unions, normalized duplicate rejection and refusal to overwrite existing destinations.
`src/qawrench/a11y/schemas/sarif-output.schema.json` is our constrained diff structural output contract;
`src/qawrench/a11y/schemas/migration-sarif-output.schema.json` covers migration notes. Both are original
contracts, not copies of the full official SARIF schema. A separate implementation-time check
also validated axe swap/nested and mixed-runner Pa11y outputs against the fetched
full SARIF 2.1.0 schema; that schema is not shipped or fetched by tests.
