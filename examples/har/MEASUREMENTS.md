The timings cover different scopes and must not be added together or treated
as a speedup ratio. They are an observed maintenance cost on this host, not a
replay benchmark. A separate run with the system CPython 3.14.4 also passed;
timings naturally differed.

The synthetic baseline is deliberately mismatched by its origin and volatile
query key. The independent intended-request oracle asks for the fixture origin
without that key. Recovering these matches verifies the explicit transformation;
it does **not** establish equivalent dynamic backend behavior, real-site match
improvements, lower browser replay latency or market demand. Dropping a key
on an arbitrary real fixture may be wrong or produce conflicts. No runtime
speedup is claimed. All 1,000 response objects and every field except the
specified URL/query metadata changes are asserted equal; repeated application,
standard-JSON round-trip and the actual CLI file path are exercised.
